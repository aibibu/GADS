# iPhone 控制与 Reqable 抓包

这份说明记录我们本地使用的两条手机控制路径，以及带电脑代理时的抓包步骤。
GADS 负责设备控制，Reqable 负责网络抓包，两者可以分别使用。

## 工具各自做什么

| 工具 | 用途 | 使用条件 |
| --- | --- | --- |
| iPhone 镜像 | 在 Mac 上直接操作一台 iPhone | 手机锁屏，保持无线连接；按系统提示连接 |
| GADS Hub / Provider | 在网页中控制设备，或接自动化测试 | MongoDB、Hub、Provider 都运行，设备配置和 WDA 可用 |
| WebDriverAgent（WDA） | 接收 GADS 的 iOS 点击、滑动等指令 | 为当前手机签名并安装兼容的 WDA |
| 手机 Reqable | 将手机请求交给电脑抓包 | 手机与电脑能通过局域网通信，协同已连接 |
| 电脑 Reqable | 显示请求、响应，并转发到上游代理 | 代理监听已开启，HTTPS 证书配置正确 |
| 电脑现有 HTTP 代理 | 提供上网出口 | 上游端口确实可用 |

当前采用的网络路径是：

```text
手机 Safari / App
  → 手机 Reqable 的已有 VPN 配置
  → 电脑 Reqable（局域网地址:9000）
  → 电脑二级 HTTP 代理（127.0.0.1:1082）
  → 目标网站
```

USB 用于连接设备及 GADS 的设备通信；上述 Reqable 协同流量通过局域网传输。
`127.0.0.1:1082` 填在电脑 Reqable 中，指电脑上的代理，不能拿这个地址给手机连接电脑。
端口来自本次本地配置，更换环境时要重新核对。

## 最快恢复：iPhone 镜像 + Reqable

### 1. 接管手机

1. 手机保持 USB、Wi-Fi 连接。
2. 按手机侧键锁屏，在 Mac 打开「iPhone 镜像」。
3. 若显示「iPhone 正在使用中」，先锁屏，再点镜像窗口里的「连接」。
4. 镜像内可以点击手机界面。`⌘1` 返回主屏幕，`⌘2` 打开 App 切换器，`⌘3` 打开搜索。

本次已用系统镜像成功控制 iPhone SE 第三代。旧 GADS 配置曾使用另一台手机，不能直接把旧设备配置当作当前手机配置。
镜像输入网址时使用英文输入法；中文输入法可能把冒号或文字转换成另一种内容。
本次镜像的剪贴板粘贴存在延迟，不依赖粘贴来验证网络连接。

### 2. 设置电脑 Reqable

1. 打开 Reqable，确认代理在监听，并记录界面显示的电脑局域网地址和端口。本次端口为 `9000`。
2. 打开「二级代理」，新增或检查规则：

   | 配置 | 本次值 |
   | --- | --- |
   | 名称 | `Local upstream 1082` |
   | 地址 | `127.0.0.1:1082` |
   | 匹配模式 | 允许模式 |
   | 匹配规则 | `*` |

3. 保存，勾选「启用二级代理」，并选中这条规则。
4. 核对地址中的冒号是英文 `:`，没有全角标点或空格。

二级代理的作用是让被抓取的手机请求继续经过电脑已有代理。
本次在响应总览中看到后端服务端地址为 `127.0.0.1:1082`，确认了这一段转发路径。

### 3. 手机与电脑协同

1. 手机打开 Reqable，在「协同」中连接电脑；可以使用电脑提供的二维码。
2. 已配对时，直接检查页面是否显示「设备已连接」。
3. 如果提示手机和电脑的根证书不一致，使用「同步」，再到手机 Reqable 的「证书管理」检查状态。
4. 本次手机已有证书，显示「证书已安装」，并复用了已有 VPN 配置。
5. 在已连接的协同页点击抓包按钮，确认按钮进入运行状态，手机状态栏出现 VPN。
6. 电脑 Reqable 应显示一个已连接的手机，打开普通网页时出现新请求。

如果是首次安装证书，还需要按 Reqable 的指引安装描述文件，并在 iPhone「设置 → 通用 → 关于本机 → 证书信任设置」中确认所安装的证书。
证书安装与信任是首次配置步骤；已有证书可用时不重新生成证书。

### 4. 验收抓包是否可用

判断标准是电脑中出现实际的 `GET` / `POST` 等 HTTPS 请求，并能打开其「响应体」读取内容。
只有 `CONNECT 200` 只能证明隧道建立，不能证明已读取 HTTPS 正文。

本次验证结果：

- 手机 Safari 的普通 HTTPS 请求显示 `GET`、HTTP `200`。
- 电脑可读取响应 JSON 正文。
- 客户端来自手机局域网地址，后端经过 `127.0.0.1:1082`。
- 手机普通网页可加载。

Apple 等域名可能命中 SSL 绕过规则，此时仅显示 `CONNECT` 属于另一种情况。
应对真正需要诊断的域名检查是否有可读的请求和响应正文。
本次验证没有提交充值或付款，也还没有生成新的结账 HAR。

## 抓取新的结账流程

1. 开始一个新的 Reqable 调试会话，便于区分测试流量与本次操作。
2. 在手机进入需要检查的页面，选择档位并打开结账页面。
3. 先确认结账接口返回的字段、付款组件初始化请求及响应，通常不必立即完成付款。
4. 如需实际付款，由操作者确认金额并执行。
5. 停止抓包，导出包含请求与响应正文的 HAR，保存在本地。
6. 将新 HAR 导入我们的协议工具，与旧录制进行比较后再更新工作流。

这次 n8n 问题应优先比较「创建结账」响应中的支付通道与字段结构，再检查下游组件初始化需要的字段。
不要仅因一个 GET 节点报参数错误就跳过它；后续节点可能依赖其输出。

HAR、Cookie、Session、Token、卡号、CVV、设备标识、签名证书及私钥不提交到这个源码仓库。

## 恢复 GADS 控制路径

系统镜像和 GADS 是不同的控制入口。USB 已识别手机，并不等于 GADS 已可以控制它。
本次抓包采用系统镜像；检查时 GADS Hub 和 Provider 没有运行，没有声称当前手机已通过 GADS 验收。

### 原有部署结构

- MongoDB：保存 Hub / Provider / Device 配置，原本本地端口为 `27018`。
- Hub：Go 服务，原本本地使用 `10000` 端口。
- Provider：读取同一 MongoDB 中的配置并连接设备。
- WDA：安装在被控制的 iPhone 上，由 Provider 启动。

### 恢复顺序

1. 启动 MongoDB，核对原有数据是否仍在。
2. 按 [Hub 文档](./hub.md) 启动 Hub，连接正确的 MongoDB。
3. 在 Hub 管理页面检查 Provider 的主机地址、昵称和配置。
4. 在 Devices 中为当前手机建立或更新设备配置，并分配给 Provider。
5. 按 [Provider 文档](./provider.md) 准备并签名 WDA。上游要求使用兼容的 [GADS WDA fork](https://github.com/shamanec/WebDriverAgent)，原版 WDA 的接口不完全相同。
6. 启动 Provider，等待设备在线，再测试点击、滑动、文字输入与视频画面。
7. 更换手机后，重新检查设备标识、签名、开发者模式、WDA 配置及屏幕尺寸。

启动参数与常驻方式见上游文档：

- [Hub 设置](./hub.md)
- [Provider / WDA 设置](./provider.md)
- [macOS 服务设置](./macos-service.md)

## 此 fork 保留的本地 Go 改动

分支：`aibibu/phone-control`。`main` 保留上游版本；此分支基于原来本地已经使用的版本，尚未合并上游后续更新。

| 改动 | 作用 |
| --- | --- |
| `cmd/providerfix` | 检查 Provider，必要时修正 MongoDB 中的主机地址 |
| WDA Bundle ID 处理 | 避免已包含 `.xctrunner` 的 Bundle ID 被重复添加后缀 |
| `GADS_SKIP_WDA_INSTALL=true` | 在 WDA 已经正确安装时跳过自动安装阶段 |
| iOS 控制坐标换算 | 根据 WDA 窗口尺寸换算点击、长按、滑动等坐标 |

`GADS_SKIP_WDA_INSTALL` 只跳过自动安装，不跳过设备信任、WDA 签名或启动过程。
现有坐标处理仍有横屏适配及手势中重复读取窗口尺寸的待完善项，不能视为所有设备和方向都已验证。

Go 部分按仓库现有 AGPL-3.0 许可保留。`hub-ui` 有单独许可，本次未修改或额外打包上传其内容。
